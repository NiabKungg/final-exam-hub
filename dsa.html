2.1 Bubble Sort — เปรียบทีละคู่ ตัวใหญ่ "ลอย" ไปท้าย

เปรียบเทียบเหมือนจัดแถวนักเรียนตามส่วนสูงโดยยืนคู่กันเทียบทีละคู่จากหน้าไปหลัง — ผ่านรอบ (pass) ละ 1 รอบ คนที่สูงสุดที่ยังไม่ถูกล็อกจะถูกดันไปสุดท้ายพอดี

void BubbleSort(int[] a, int n) {
  for (int i = 0; i < n - 1; i++)            // n-1 pass
    for (int j = 0; j < n - i - 1; j++)      // โซนท้ายที่เรียงแล้วไม่ต้องเทียบ
      if (a[j] > a[j+1]) swap(a[j], a[j+1]);
}

ถ้าใหญ่กว่าลูกน้อยกว่า → สลับกับลูกตัวนั้น · ทำซ้ำจนเล็กกว่าลูกทั้งคู่ หรือไม่มีลูก
3 เคสตอนจมลง (จากสไลด์)① ไม่มีลูก → จบทันที ② มีลูกเดียว (ซ้าย) → เทียบแล้วสลับได้ ③ มีสองลูก → สลับกับ ลูกที่น้อยกว่า เท่านั้น (สลับกับตัวใหญ่แล้ว heap พัง!)

5 · Binary Search Tree — สร้างจากตัวเลข + เติมโค้ด

กฎเหล็ก BSTทุก node: ค่าซ้ายทั้ง subtree < ตัวเอง < ค่าขวาทั้ง subtree — เหมือนสารบัญหนังสือที่จัดกลุ่มเลข: อยากหาค่าอะไรแค่เดิน "เล็กกว่า → ซ้าย / ใหญ่กว่า → ขวา" ครึ่งทรีทิ้งทุกชั้น → O(log n) · ถ้าใส่ข้อมูลเรียงแล้วจะทรุดเป็น linked list → O(n) (ต้นไม้ตัวโกง — จึงต้องมี AVL)

5.2 เติมโค้ด searchIter(int key) (ข้อเติม 1 บรรทัด — จากสไลด์ตรง ๆ)

public TreeNode searchIter(int key) {
    TreeNode current = root;
    while (current != null) {
        if (key == current.data) return current;
        if (key < current.data) current = current.left;
        else current = current.right;
    }
    return null;   // เดินหลุดต้น = ไม่เจอ
}
จำแนวเติมโค้ด BSTเงื่อนไขสามแบบเสมอ: == คืน node · < ไปซ้าย · ไม่ใช่ไปขวา · ถ้าโจทย์เติมinsert: เจอช่องว่าง (left/right == null) → current.left = new TreeNode(d) อย่าลืมตั้ง parent ถ้า class มี parent

สูตรตอบข้อ AVL ในข้อสอบ (ทำตามลำดับ ได้คะแนนเต็ม) ① insert ทีละตัวแบบ BST ปกติ → ② จาก node ที่เพิ่งใส่ ไต่ขึ้นหา "node แรกที่ BF = ±2" → ③ ดูทางเดินจาก node นั้นไปยังตัวใหม่: ซ้าย-ซ้าย = หมุนขวา / ขวา-ขวา = หมุนซ้าย / ซ้าย-ขวา = LR / ขวา-ซ้าย = RL → ④ วาด tree ใหม่ แล้วเขียน BF ทุก node ให้ดูว่า balance แล้ว → ทำซ้ำทุกครั้งที่ insert

ตัวอย่างไล่จริง: insert 10, 20, 30, 40, 50, 25

10, 20, 30

พอใส่ 30 → BF(10) = −2 (RR) → หมุนซ้ายที่ 10 → ได้ 20 เป็นราก (ลูก: 10, 30)

40

เข้าขวาของ 30 · BF(20) = −1, BF(30) = −1 → ยัง balance ไม่ต้องทำอะไร

50

เข้าขวาของ 40 → BF(20) = −2, เส้นทาง ขวา-ขวา (RR) → หมุนซ้ายที่ 20 → 30 ขึ้นเป็นราก (ลูกซ้าย 20, ขวา 40; 40 ลูกขวา 50)

25

เดิน: <30 ซ้าย, >20 ขวา → ลูกขวาของ 20 → BF(30) = +2 เพราะซ้าย (20) สูง 2 ขวา (40) สูง 1 → เส้นทาง ซ้าย-ขวา (LR) → หมุนซ้ายที่ 20 แล้วหมุนขวาที่ 30 → 25 ขึ้นเป็นราก (ลูกซ้าย 20, ขวา 30, 30 ลูกขวา 40, 40 ลูกขวา 50) ✓

ลบใน AVL

ทำเหมือน BST delete แต่หลังลบต้องไต่ขึ้นเช็ก BF ทุกบรรพบุรุษ (rotate ได้หลายรอบ — insert หมุนได้สูงสุด 1 ครั้ง แต่ delete หมุนได้ O(log n) ครั้ง) · เงื่อนไขหมุนหลังลบดูเคสลูกของลูกด้วย: bf>1 && bf(ลูกซ้าย)≥0 → หมุนขวา, bf>1 && bf(ลูกซ้าย)<0 → LR, และกลับกันฝั่งขวา

7 · Splay Tree — ตัวที่เพิ่งถูกใช้ "ปีนขึ้นราก"

แนวคิดทุกครั้งที่ search/insert (และก่อน delete) จะ splay = หมุนตัวที่ถูกเข้าถึงขึ้นไปเป็นราก · ไอเดียเหมือนแอปที่จำว่าคุณเปิดอะไรบ่อย — ของที่ใช้ล่าสุดอยู่บนสุด เปิดซ้ำเร็วมาก · ไม่มีการเก็บ height (ไม่มี book-keeping) · เกณฑ์เวลาแบบ amortized O(log n) (เฉลี่ยต่อการทำงานหลาย ๆ ครั้ง)

8 · Graph — Kruskal (MST) และ Dijkstra (Shortest Path)

8.1 Kruskal — "เลือกเส้นถูกที่สุดทีละเส้น ถ้าไม่ทำวงจร" ⭐

เปรียบเทียบเหมือนวางสายไฟเชื่อมหมู่บ้าน 6 หมู่ด้วยสายถูกสุด: เรียงสายจากถูกไปแพง แล้วหยิบมาใช้ทีละเส้น — เส้นไหนทำให้เกิดวงจร (เชื่อมหมู่บ้านที่ต่อถึงกันอยู่แล้ว) ให้ทิ้ง · เครื่องมือตรวจวงจร = Union-Find (find ว่าสองจุดอยู่ "กลุ่ม" เดียวกันไหม, union = รวมกลุ่ม)
โจทย์แนวเดียวกับสไลด์: A–G กับน้ำหนัก A-B:7 · B-C:8 · A-D:5 · B-D:9 · B-E:7 · C-E:5 · D-E:15 · D-F:6 · E-F:8 · F-G:11 · E-G:9

เรียงเส้นจากน้อยไปมาก

A-D:5 · C-E:5 · D-F:6 · A-B:7 · B-E:7 · E-F:8 · B-C:8 · E-G:9 · B-D:9 · F-G:11 · D-E:15

A-D(5) ✓ · C-E(5) ✓ · D-F(6) ✓

กลุ่มเกิดใหม่: {A,D,F}, {C,E}, {B}, {G}

A-B(7) ✓

B รวมเข้ากลุ่ม {A,D,F,B} · B-E(7) ✓ รวมสองกลุ่ม → {A,B,C,D,E,F}

E-F(8) ✗ · B-C(8) ✗

ทั้งคู่ "ปลายทั้งสองอยู่กลุ่มเดียวกันแล้ว" → ทิ้ง (จะเกิด cycle)

E-G(9) ✓

จำนวนเส้น = 6 = n−1 (7 จุด) → จบ (เส้นที่เหลือไม่ต้องดู)
MST = A-D(5) + C-E(5) + D-F(6) + A-B(7) + B-E(7) + E-G(9) · รวม = 39
เขียนตอบ: ตารางเรียงน้ำหนัก + ทำเครื่องหมาย ✓/✗ พร้อมเหตุผล (same component → cycle) + วาด MST ที่ได้ + รวมน้ำหนัก

Union-Find ที่ยกมาใช้ (โค้ดย่อ)

int find(int x) {                 // หา "หัวโจก" ของกลุ่ม
  while (parent[x] != x) x = parent[x];
  return x;
}
void union(int a, int b) {
  int ra = find(a), rb = find(b);
  if (ra != rb) parent[rb] = ra;  // รวมกลุ่ม (เวอร์ชัน + path compression & union by rank เร็วกว่า)
}

8.2 Dijkstra — ระยะสั้นสุดจากจุดต้น ⭐ (ออก "แสดงขั้นตอน + ผลลัพธ์")

เปรียบเทียบเหมือนแผนที่ GPS: ทำเครื่องหมายจุดที่ "แน่ใจระยะสั้นสุดแล้ว" ทีละจุด (จุดที่ใกล้สุดเสมอ) แล้วใช้จุดนั้น "ปรับปรุง (relax)" ระยะของเพื่อนบ้าน: ถ้า ผ่านฉันไปสั้นกว่าที่จำไว้ → แก้ระยะ + จดว่ามาจากฉัน

ในข้อสอบให้: (1) ตารางเดินทีละผลัดแบบนี้ (2) วาด shortest-path tree หรือเขียน path + ระยะรวม (3) จุดที่ dist ยัง ∞ = เข้าไม่ถึง
เปรียบเทียบ Prim vs Dijkstra vs Kruskal (ชอบออกถามความต่าง) สามตัวเป็น greedy ทั้งหมด · Prim: ปลูกต้นไม้จากจุดเริ่ม เลือกเส้น "ถูกสุดที่เชื่อมต้นไม้กับข้างนอก" (key[v] = น้ำหนักเส้น) ได้ MST · Dijkstra: เลือกจุดที่ "ระยะสะสมสั้นสุด" (dist[v] = ระยะรวมจากต้นทาง) ได้เส้นทางสั้นสุด — ใช้ 2 ตัวนี้สลับกันไม่ได้! MST ไม่จำเป็นต้องให้เส้นทางสั้นสุด · Kruskal: เรียงเส้นแล้วเลือกด้วย Union-Find (ไม่ต้องมีจุดเริ่ม)

9 · เขียนโปรแกรม: Binary String ยาว K โดย 1 ห้ามติดกัน

แนวคิด (recursion)สร้างสายอักขระทีละตำแหน่ง: ตำแหน่งใหม่วาง "0" ได้เสมอ · วาง "1" ได้เฉพาะเมื่อตัวก่อนหน้าไม่ใช่ 1 — เหมือนนั่งเรียงที่นั่งโรงหนังให้คน 1 คนมีที่ว่างข้าง ๆ เสมอ · พอครบ K ตัว พิมพ์คำตอบ
static void gen(int remain, String s, char last) {
    if (remain == 0) {                 // สร้างครบ K ตัวแล้ว
        System.out.println(s);
        return;
    }
    gen(remain - 1, s + "0", '0');     // วาง 0 ได้เสมอ
    if (last != '1') {                 // 1 ห้ามติดกับ 1
        gen(remain - 1, s + "1", '1');
    }
}
// เรียกใช้: gen(K, "", '0');

ไล่มือ K = 3 (มี 5 คำตอบ)
